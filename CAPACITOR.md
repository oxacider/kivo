# KIVO × Capacitor (Android) — Integration Guide

This document explains how the KIVO Android app (Capacitor wrapper) loads the real
Next.js web application, and what is required for it to work end-to-end
(Firebase auth, realtime chat, push).

## Architecture

The KIVO web app is a **server-rendered Next.js app** (`output: "standalone"` in
`next.config.ts`). It cannot be statically bundled into the APK, so the Android
WebView loads the app from a **server URL** at runtime (`server.url` in
`capacitor.config.ts`), exactly like a browser pointing at the site.

```
┌────────────────────────────┐        HTTPS / HTTP          ┌──────────────────┐
│  Android app (WebView)     │  ──────────────────────────► │  KIVO Next.js    │
│  com.kivo.messenger        │      CAPACITOR_SERVER_URL    │  server          │
│  (offline.html fallback)   │ ◄──────────────────────────  │  (Firebase SDK)  │
└────────────────────────────┘                              └──────────────────┘
```

- **`webDir: 'out'`** is only a local fallback shell (`index.html` + `offline.html`).
  It is generated by `.zscripts/ensure-webdir.cjs` so `cap sync` is reproducible on
  fresh clones.
- **`server.errorPath: 'offline.html'`** shows a KIVO-branded offline page whenever
  the configured server URL cannot be reached (offline / server down). This keeps
  the placeholder fallback even in production `server.url` mode.

## Loading the real app

### Local dev / LAN testing

```bash
# 1. Start the Next.js dev server
bun run dev          # listens on :3000

# 2. Sync + run on Android, pointing at your LAN IP (same Wi-Fi as the device)
CAPACITOR_SERVER_URL=http://192.168.1.105:3000 npx cap sync android
cd android && ANDROID_HOME=$HOME/Android/Sdk ./gradlew installDebug

# Or live-reload flow:
CAPACITOR_SERVER_URL=http://192.168.1.105:3000 npx cap run android -l
```

Notes:
- `cleartext: true` in `server.*` permits the `http://` dev origin. Do **not** use
  `http` for production.
- From the emulator, the host machine is reachable at `http://10.0.2.2:3000`
  instead of the LAN IP.

### Production

```bash
# 1. Deploy the Next.js server (see .zscripts/build.sh for the standalone flow)
# 2. Build the APK pointing at the deployed origin
CAPACITOR_SERVER_URL=https://kivo.example.com bun run build:android
```

`build:android` requires `CAPACITOR_SERVER_URL` (it hard-errors otherwise) and
chains: `next build` → copy `logo.png` → `ensure-webdir` → `cap sync android`.

## Firebase Authentication in the WebView

Firebase Auth (email/password) runs in the WebView exactly like in a browser.
Two requirements:

1. **Authorized domains (Firebase Console)** — the origin the WebView loads must be
   listed under *Authentication → Settings → Authorized domains*:
   - Production: `https://kivo.example.com` (your real domain).
   - Local dev via LAN IP: `http://192.168.1.105` (and `http://localhost` is
     pre-authorized).
   - The Firebase Auth domain `kivo-96303.firebaseapp.com` is already in
     `server.allowNavigation` so popup/redirect auth stays inside the WebView.

2. **Same-origin API calls** — the Next.js server must proxy Firebase Admin
   operations (`/api/auth/*`, `/api/users/*`) as it already does for web; no
   extra WebView work is needed.

> **If sign-in fails with `auth/unauthorized-domain`**, the origin is not in the
> authorized-domains list above — add it in the Firebase Console.

## Realtime chat & presence

Realtime chat uses Firestore (messages snapshot) and the Firebase Realtime
Database (presence/typing). These are serverless Firebase services, so they work
in the WebView with no extra configuration beyond the Firebase web SDK being
initialized (env vars in `.env`).

- **Mini-service** (`mini-services/kivo-chat-service`, Socket.IO on :3003) is a
  legacy socket layer; modern chat flows go through Firestore/RTDB directly and
  do not require it inside the WebView.
- **Push notifications** (`@capacitor/push-notifications`) require
  `android/app/google-services.json` to be added to the Android project — until
  then the app builds and runs, but native FCM push is disabled (the web app's
  FCM token flow still works in the WebView).
- **Network security** — `android.allowMixedContent: true` is set for dev
  convenience; tighten for production if desired.

## Verification checklist

- [ ] `npx cap doctor` → "Android looking great!"
- [ ] `npx cap sync android` completes with all 7 plugins found
- [ ] `./gradlew assembleDebug` → BUILD SUCCESSFUL, `app-debug.apk` produced
- [ ] `aapt dump badging app-debug.apk` → launchable-activity
      `com.kivo.messenger.MainActivity`
- [ ] WebView loads the real app (server reachable) — not the placeholder shell
- [ ] Killing the server / going offline shows the branded `offline.html` fallback
- [ ] Firebase sign-in works (origin authorized in Firebase Console)
- [ ] Message send + realtime receive works inside the WebView
